# Regex Injection and ReDoS in scan-tool.js description processing

**ID:** vuln-0002
**Severity:** MEDIUM
**Found:** 2026-07-26 03:36:34 UTC
**Target:** /workspace/Tool-Calling
**CWE:** CWE-185
**CVSS:** 4.2
**Fix Effort:** Trivial

## Description

The scan-tool.js script constructs a regular expression using user-controlled values from GitHub URLs (owner and repo names) without escaping special regex characters, potentially allowing regex injection and ReDoS attacks.

## Evidence

From scripts/scan-tool.js line 204:
```javascript
description = description.replace(new RegExp(`Contribute to ${owner}/${repo}.*?GitHub\\.?`, 'i'), '').trim();
```

The owner and repo values are extracted from the user-provided URL at lines 146-147:
```javascript
const githubRegex = /^https?:\/\/github\.com\/([^/]+)\/([^/]+)(?:\/(?:tree|blob)\/([^/]+)\/(.+))?\/?$/;
const match = url.match(githubRegex);
const [, owner, repo, branch, subpath] = match;
```

While [^/]+ prevents path traversal, it does not prevent regex metacharacters.

## Impact

An attacker who controls a GitHub repository name containing regex metacharacters could cause unexpected matching behavior or, in worst case, trigger catastrophic backtracking in the regex engine leading to denial of service during tool scanning operations.

## Technical Analysis

In scripts/scan-tool.js line 204, the code constructs a regex using interpolated values from the GitHub URL:

```javascript
description = description.replace(new RegExp(`Contribute to ${owner}/${repo}.*?GitHub\\.?`, 'i'), '').trim();
```

The owner and repo values come from parsing the user-provided URL. While the URL validation regex (`/^https?:\/\/github\.com\/([^/]+)\/([^/]+).../`) restricts these to non-slash characters, it does not prevent regex metacharacters like `.`, `*`, `+`, `?`, `(`, `)`, `[`, `]`, `^`, `$`, `{`, `}`, `|`, `\`. 

If an attacker creates a GitHub repository with a name containing these characters (which GitHub allows), the resulting regex could:
1. Match unintended strings due to unescaped metacharacters
2. Cause catastrophic backtracking with crafted input patterns
3. Alter the description cleaning logic unpredictably

Additionally, semgrep flagged this as a potential ReDoS vector because the RegExp() constructor is called with a dynamically constructed pattern rather than a hardcoded literal.

## Proof of Concept

1. Create a GitHub repository with a name containing regex metacharacters, e.g., test.*?.+
2. Run: node cli.js add https://github.com/attacker/test.*?.+
3. Observe that the scanner's description cleaning regex matches unintended strings due to the unescaped . and * characters in the repo name.
4. For ReDoS testing, craft a repository name that triggers catastrophic backtracking when combined with certain description content.

```
// Proof of concept: demonstrate regex injection via repo name
const owner = "test";
const repo = ".*?.+"; // Contains regex metacharacters

// Original vulnerable code pattern:
const vulnerableRegex = new RegExp(`Contribute to ${owner}/${repo}.*?GitHub\\.?`, 'i');
console.log("Vulnerable regex pattern:", vulnerableRegex.source);
// Output: Contribute to test/.*?.+.*?GitHub\.?
// This matches ANYTHING between "test/" and "GitHub" due to unescaped .*?

// Safe alternative using escape:
function escapeRegex(str) {
  return str.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
}
const safeRegex = new RegExp(`Contribute to ${escapeRegex(owner)}/${escapeRegex(repo)}.*?GitHub\\.?`, 'i');
console.log("Safe regex pattern:", safeRegex.source);
// Output: Contribute to test/\.\*\?\.\+.*?GitHub\.?
// This correctly treats the metacharacters as literals
```

## Remediation

Escape special regex characters in owner and repo names before interpolating them into the RegExp constructor. Use a helper function like String.prototype.replace(/[.*+?^${}()|[\]\\]/g, '\\$&') to escape all regex metacharacters. Alternatively, use string.includes() or string.startsWith() for simple substring matching instead of regex when possible.

## Assumptions

Requires an attacker to control a GitHub repository name with regex metacharacters. GitHub allows most characters in repository names except / and ., making this attack feasible.
