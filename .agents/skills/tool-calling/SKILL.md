# Tool-Calling 全自動工具調用與多工具協同開發 SOP

> **觸發咒語**: 「啟動全自動工具調用模式：[用戶的任務描述]」或「啟動全自動工具調用模式」

當用戶在其他專案中使用喚醒咒語啟動此模式時，Agent 必須嚴格遵循以下四階段 SOP 執行：

---

## 階段 1：模糊需求白話釐清與引導 (Interactive Jargon-Free Clarification)

用戶提供的任務描述往往非常模糊（例如：「幫我做一個自動整理股價發到通訊軟體的系統」）：
1. **禁止盲目猜測或急於給出粗糙解答**：影響開發路徑或結果產出的關鍵問題必須先釐清。
2. **透過白話向用戶提問**（摒棄生澀專業術語，使用直覺情境提問）：
   - **開發語言與環境**：習慣 Python, Node.js, Java 或無語言限制（可一鍵執行即可）？
   - **真實應用目的**：是為了給 AI 助手閱讀做摘要/知識庫、自動化按鈕測試，還是大量數據抓取？
   - **畫面與防護**：處理的目標是否包含複雜動態畫面、滾動加載或防爬蟲機制？
3. 亦可執行 `node cli.js interview "<任務描述>"` 自動啟動問答對接。

---

## 階段 2：多工具篩選與鏈式協同規劃 (Multi-Tool Selection & DAG Chain Planning)

專案開發所需工具往往不只一個（例如：`爬蟲/擷取工具` + `資料解析/LLM工具` + `簡報/訊息發送工具`）：
1. 執行 `node cli.js plan "<長任務描述>"` 或呼叫 `planToolChain()` 演算法。
2. 自動將長任務分解為順序子步驟，為每個步驟匹配 **最適首選工具 (Primary Tool)** 與 **備選競品 (Alternatives)**。
3. 導出結構化執行流程圖（Data Flow DAG）與步驟介面格式（Input/Output Formats）。
4. 亦可執行 `node cli.js compare "<需求>"` 印出五維度競品適配矩陣，比較 Trade-offs。

---

## 階段 3：彈性協同開發與執行 (Flexible Synergy & Collaboration)

工具的協作方式彈性不拘：
- **整合進新專案**：可直接作為 `npm` / `pip` 開發相依套件安裝進目標新專案。
- **獨立服務運行**：亦可作為獨立 CLI 工具、Docker 容器、背景 Daemon 或本機 MCP 服務運作。
- **執行前環境預檢**：呼叫 `node cli.js verify-environment <tool-id>` 確保 Node, Python, Docker 等相依環境完全就緒。

---

## 階段 4：任務結束自動解耦與零負擔清理 (Post-Task Decoupling & Cleanup)

開發與確效驗證完成後：
1. **零負擔原則**：若新專案後續不需要永久保留該工具，必須執行 `node cli.js cleanup <tool-id>` 進行自動卸載與解耦。
2. 確保目標專案代碼庫保持 MECE 乾淨整潔，絕不殘留冗餘依賴或增加目標專案的維護負擔。
