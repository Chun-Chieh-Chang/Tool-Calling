## 1. 工具：天花板分析現在能列出逐題失敗

`scripts/ceiling-analysis.js` 原本只印聚合數字。本次新增旗標（純邏輯抽到
`core/ceiling.js`，由 `tests/ceiling-analysis.test.js` 以秒級小樣本守門）：

```bash
npm run ceiling                       # 聚合表（輸出與改動前逐字相同）
node scripts/ceiling-analysis.js --failures                 # 逐題失敗清單
node scripts/ceiling-analysis.js --failures --recall-miss   # 只看召回缺口
node scripts/ceiling-analysis.js --failures --rank-loss     # 只看排序問題
node scripts/ceiling-analysis.js --json                     # 機器可讀（供後續分析）
```

分類刻意分成兩種（對應 MEMORY §2「多數失敗是排序問題，不是召回問題」）：

- **召回缺口**：正解完全沒進 top-50 → 真正的召回問題（詞彙鴻溝、索引缺詞）
- **排序問題**：正解進榜但排名 > 5 → 權重／rerank 的活

## 4. 新證據：評測集本身有 9 題含簡體字，且這確實壓低分數

用專案自己的偵測器（`scripts/fix-simplified.js` 的 `findSimplified()`，內建保守 S2T 表）
掃 257 題，**9 題含簡體字**：c14、c77、c79、c106、c144、c145、c146、c147、c148。
其中 5 題落在失敗清單（c144 召回缺口；c77 排名 26、c79 排名 39、c146 排名 23、c148 排名 9）。

### 配對 A/B（同一題、只把 query 轉繁體，其餘全不動）

| id | 原句（簡體） | 轉繁體後 | 變化 |
|---|---|---|---|
| c14 | 4 | 2 | ↑ |
| c77 | 26 | 26 | ＝ |
| c79 | 39 | 9 | ↑ |
| c106 | 1 | 1 | ＝ |
| c144 | **未進榜** | **7** | ↑ |
| c145 | 1 | 1 | ＝ |
| c146 | 23 | 7 | ↑ |
| c147 | 4 | 1 | ↑ |
| c148 | 9 | 4 | ↑ |

**改善 6 題、不變 3 題、變差 0 題**（n=9；符號檢定單尾 p = 1/2⁶ ≈ 0.016）。
唯一那題 semantic 召回缺口（c144）在轉繁體後直接進到第 7 名。

**但不要過度推論**：9 題裡有 4 題即使帶簡體字也照樣成功（c14、c106、c145、c147），
所以簡繁只是**加重因子**，對 42 題失敗只有 5 題有解釋力。其餘 37 題與簡繁無關。

## 5. 建議（需裁決——兩項都動到基線或 SSOT，我不會擅自改）

### 建議 A：評測集簡繁清洗 → 發 v1.4.0，並重跑全部基線

- 理由：評測題是繁體專案，卻有 9 題混入簡體字；它們量到的是「簡繁不匹配」而非
  「檢索能力」。清洗後量出來的數字才反映真實能力。
- 代價：**v1.3.0 與 v1.4.0 基線不可比較**（MEMORY §1 的既有規則），
  Hit@1／天花板／ablate:v5 全部要重跑一次並重新記錄。
- 做法：只做簡→繁轉換、不改語意、不動 expected；版本號與 `methodology` 欄位註明原因。

### 建議 B：查詢端簡轉繁正規化（先離線量測，再決定是否上線）

- 理由：真人使用者（尤其中文輸入法預設簡體者）也會打簡體查詢。本專案已有
  「偵測（`findSimplified`）與轉換（`toTraditional`，opencc）職責分離」的既有設計，
  把它接到查詢入口即可。
- 必須遵守：**先離線量測**（用 A/B 對照跑 benchmark／ceiling），確認無回歸才上線；
  且因為會改變檢索行為，**所有既有基線數字都要標註「B 之前／之後」**。
- 注意：不可無條件套用 opencc（MEMORY §4：會把已繁體的改錯）——要用 `findSimplified`
  當守門，只有真的含簡體才轉。

### 紀律（已在 MEMORY §5，此處再確認落檔）

🔴 **每次重新編譯詞檔（`npm run compile:wiki`）都必須重跑 `npm run ablate:v5`**——
最適 V5 權重取決於詞檔品質，詞檔一換，舊權重的最適性即失效。
