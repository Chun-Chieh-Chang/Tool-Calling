# skills.sh 與 Tool-Calling 專案差異分析

## 執行摘要

兩者定位不同：**skills.sh 是技能發現平台**，**Tool-Calling 是工具管理與調用系統**。現在通過整合，Tool-Calling 已能聚合 skills.sh 作為技能來源之一。

---

## 一、核心定位差異

### skills.sh（Vercel 官方）

| 維度 | 說明 |
|------|------|
| **定位** | Agent Skills 發現與分發平台 |
| **所有者** | Vercel Labs |
| **規模** | 110万+ 技能，290万+ 安裝 |
| **目標用戶** | AI Agent 使用者（Claude, Cursor, Codex 等） |
| **核心價值** | 發現新技能、查看熱門排行榜、一鍵安裝 |

**主要功能：**
- 📱 Web 界面瀏覽技能
- 🔥 熱門技能排行榜（按安裝數排序）
- ➕ 一鍵安裝到各類 AI Agent
- 📝 技能首頁展示（README/SKILL.md）
- 🔍 分類瀏覽（PDF、PPT、測試等）

### Tool-Calling 專案

| 維度 | 說明 |
|------|------|
| **定位** | 本地工具管理與自動化調用系統 |
| **所有者** | 個人/團隊維護 |
| **規模** | 538+ 工具，2118 追蹤倉庫 |
| **目標用戶** | 開發者、AI Agent 架構師 |
| **核心價值** | 智能搜尋、競品比對、多工具鏈規劃、沙盒執行 |

**主要功能：**
- 🔍 自然語言搜尋工具
- 📊 五維度競品重排矩陣
- 🗺️ 多工具鏈 DAG 規劃
- 🛡️ Docker 沙盒安全執行
- 📈 每週 GitHub 漲星探勘
- 🤖 MCP Server 集成（供 AI Agent 調用）

## 二、數據來源對比

### skills.sh 的數據來源

```
┌─────────────────────────────────────────┐
│           skills.sh 生態系               │
├─────────────────────────────────────────┤
│  • 官方技能庫 (110万+)                   │

│  • 官方認證標籤                          │
└─────────────────────────────────────────┘
         ↓
    統一 API 接口
         ↓
    npx skills CLI
```

**特點：**
- ✅ 單一信任來源（Vercel 官方審核）
- ✅ 統一格式標準（SKILL.md）
- ✅ 社區評分機制
- ❌ 僅限 skills.sh 平台技能

### Tool-Calling 的數據來源（整合後）

```
┌─────────────────────────────────────────┐
│        Tool-Calling 多來源聚合           │
├─────────────────────────────────────────┤
│  📦 來源 1: skills.sh (110万+ 技能)      │
│     └─ 主要來源，Vercel 官方平台          │
│                                         │
│  📦 來源 2: GitHub Search (無限)         │
│     └─ 備援來源，搜尋 SKILL.md 文件       │
│                                         │
│  📦 來源 3: 本地註冊庫 (538+ 工具)       │
│     └─ 工具級數據，包含詳細元數據         │
│                                         │
│  📦 來源 4: 追蹤池 (2118 倉庫)           │
│     └─ 歷史快照，計算漲星趨勢             │
└─────────────────────────────────────────┘
         ↓
    統一 Skill 模型 + Registry 模型
         ↓
    CLI / MCP Server / Web UI
```

**特點：**
- ✅ 多來源聚合（skills.sh + GitHub + 本地）
- ✅ 去重與智能排序
- ✅ 離線緩存支援
- ⚠️ 需要額外維護本地數據

```
                     │
         ┌───────────┼───────────┐
         ▼           ▼           ▼
    ┌────────┐ ┌────────┐ ┌────────┐
    │Skills  │ │Install │ │ Search │
```

**特點：**
- 雲端服務，無需本地部署

```
         │                    │
         └────────┬───────────┘
                  ▼
         ┌─────────────────┐
         │   Core Layer    │
         ├─────────────────┤
         │ skill-aggregator│ ← 多來源聚合
         │ skill-discovery │ ← 兼容性模組
         │ search-engine   │ ← 五維度搜尋
         │ registry        │ ← 工具註冊庫
         │ job-manager     │ ← 背景作業
         └────────┬────────┘
                  │
         ┌────────┼────────┐
         ▼        ▼        ▼
    ┌────────┐ ┌────────┐ ┌────────┐
    │skills. │ │GitHub  │ │Local   │
    │sh API  │ │API     │ │Cache   │
    └────────┘ └────────┘ └────────┘
```

**特點：**
- 本地部署，完全控制
- 離線可用（有緩存時）
- 可擴展的來源架構
- 適合企業內網部署

## 五、使用場景對比

### 適合使用 skills.sh 的場景

| 場景 | 說明 |
|------|------|
| **快速尋找技能** | 只想找到 PDF/PPT 處理技能並安裝 |
| **瀏覽熱門技能** | 想了解当前最流行的 Agent 技能 |
| **單一 Agent 配置** | 為某個 AI Agent 添加技能 |
| **非技術用戶** | 不想配置本地環境，直接網頁操作 |

**使用範例：**
```bash
# 簡單直接的使用
npx skills find "pdf"      # 搜尋 PDF 相關技能
npx skills add anthropic/document-skills  # 安裝技能
```

### 適合使用 Tool-Calling 的場景

| 場景 | 說明 |
|------|------|
| **複雜任務規劃** | 需要多個工具協同完成長任務 |
| **競品選型分析** | 需要比對多個相似工具的優缺點 |
| **安全執行環境** | 需要在沙盒中執行不可信工具 |
| **自動化流程** | 需要 MCP Server 集成到自動化流程 |
| **企業內部部署** | 需要離線或內網環境使用 |
| **定制化工具庫** | 需要管理內部私有工具 |

**使用範例：**
```bash
# 複雜任務流程
node cli.js plan "抓取動態網頁內容，清洗數據，生成 PPT"
node cli.js compare "playwright" "puppeteer"
node cli.js invoke playwright --headless
```

## 七、選擇建議

### 推薦使用 skills.sh 的情況

✅ 您只需要快速尋找和安裝技能
✅ 您是 AI Agent 的一般使用者
✅ 您不想維護本地環境
✅ 您需要即時更新的技能列表

### 推薦使用 Tool-Calling 的情況

✅ 您需要管理大量工具和技能
✅ 您需要複雜的任務規劃和執行
✅ 您需要竞品質比對和分析
✅ 您需要離線或內網環境使用
✅ 您是開發者或架構師

### 最佳實踐：兩者結合使用

```powershell
# 1. 先用 skills.sh 快速搜尋
npx skills find "pdf" --limit 10

# 2. 再用 Tool-Calling 深度分析
node cli.js find-skill "pdf" -n 10
node cli.js compare "pdf-tool-1" "pdf-tool-2"

# 3. 最後用 Tool-Calling 規劃執行
node cli.js plan "將 PDF 轉換為 PPT"
node cli.js invoke pdf-converter --args "input.pdf"
```

## 九、總結

| 維度 | skills.sh | Tool-Calling |
|------|-----------|--------------|
| **定位** | 技能發現平台 | 工具管理系統 |
| **規模** | 110万+ 技能 | 538+ 工具 |
| **部署** | 雲端 SaaS | 本地/私有化 |
| **核心價值** | 發現與安裝 | 管理與調用 |
| **技術深度** | 中等 | 高 |
| **擴展性** | 依賴官方 | 高度可擴展 |
| **適合用戶** | 終端用戶 | 開發者/架構師 |

**结论：**
- **skills.sh** 是「技能版 npm」— 負責發現和分發
- **Tool-Calling** 是「工具版的 Jenkins + Jira」— 負責管理和調用

兩者互補而非競爭，整合後形成了完整的 **技能發現 → 分析選型 → 自動調用** 閉環。
